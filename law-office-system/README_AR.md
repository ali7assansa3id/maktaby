# نظام إدارة مكتب المحاماة — نسخة أولية متصلة بالسحابة

## ما الذي يتضمنه؟
- تسجيل دخول بالبريد وكلمة المرور عبر Supabase Auth.
- قاعدة PostgreSQL سحابية للقضايا والموكلين والجلسات والإعلانات والمهام.
- مزامنة مباشرة عند تحميل البيانات أو حفظها، بحيث تظهر البيانات نفسها عند تسجيل الدخول من أجهزة أخرى.
- بحث داخل الجداول وتعديل وحذف وتصدير CSV.
- واجهة عربية RTL متجاوبة مع الهاتف.

## مهم قبل استخدام بيانات حقيقية
هذه نسخة MVP توضيحية وليست نظامًا قانونيًا معتمدًا أو مدققًا أمنيًا. سياسة قاعدة البيانات الحالية تجعل البيانات مشتركة بين كل المستخدمين المصادق عليهم في مشروع Supabase. هذا مناسب للتجربة فقط؛ قبل بيانات المكتب الحقيقية يجب تقرير ما إذا كانت جميع الحسابات ترى جميع الملفات، وإعداد صلاحيات الأدوار والعزل والتدقيق والنسخ الاحتياطي. لا تحفظ كلمات المرور في التطبيق ولا تضع مفتاح `service_role` في المتصفح.

## الإعداد خطوة بخطوة
1. أنشئ مشروعًا في https://supabase.com/ .
2. من لوحة المشروع افتح **SQL Editor**، ثم الصق محتوى `schema.sql` وشغّله.
3. افتح **Project Settings → API** (قد تختلف تسمية القوائم حسب إصدار لوحة Supabase). انسخ Project URL والمفتاح العام `anon` أو `publishable`. لا تستخدم `service_role` أو `secret key`.
4. افتح `index.html` من متصفح حديث متصل بالإنترنت، أدخل الرابط والمفتاح العام ثم اضغط «حفظ الإعدادات والاتصال».
5. أنشئ أول مستخدم من **Authentication → Users → Add user** في لوحة Supabase، مع تعيين بريد وكلمة مرور. بعد ذلك سجّل الدخول من الصفحة.
6. المستخدم الجديد يأخذ دور `lawyer` تلقائيًا. لتعيين مدير، لا تفعل ذلك من واجهة المتصفح. نفّذ من SQL Editor بصفتك مالك المشروع، بعد استبدال البريد:
   ```sql
   update public.profiles
   set role = 'admin'
   where email = 'admin@example.com';
   ```
   لا يوجد في هذه النسخة بعد تطبيق كامل لتفويض الأدوار على كل عملية؛ لذلك لا تعتبر حقل الدور وحده حاجزًا أمنيًا.
7. افتح الموقع على جهاز آخر وأدخل نفس إعدادات Supabase وسجّل الدخول بالحساب المصرح به. البيانات تُقرأ وتُحفظ في قاعدة البيانات السحابية.

## النشر على GitHub Pages
ارفع `index.html` إلى جذر مستودعك واجعل GitHub Pages ينشر فرع `main`/المجلد الجذر. لا ترفع ملفات سرية. رابط ومفتاح Supabase العامان ليسا بديلًا عن سياسات RLS؛ الأمان يأتي من سياسات قاعدة البيانات.

## حدود هذه النسخة
- لا توجد بعد صلاحيات أدوار دقيقة، أو سجل تدقيق للتغييرات، أو رفع مستندات، أو تنبيهات بريد/واتساب، أو تقويم متقدم.
- تصدير CSV متاح لكل جدول على حدة.
- لا توجد خدمة تلقائية لاستعادة كلمة المرور مضافة إلى الواجهة.
- حذف القضية يحذف الجلسات التابعة لها بسبب `ON DELETE CASCADE`؛ راجع هذه السياسة قبل إدخال بيانات حقيقية.
- يجب اختبار سياسات RLS بحسابات مختلفة قبل الاستخدام الفعلي، وتفعيل النسخ الاحتياطي المناسب للخطة.
